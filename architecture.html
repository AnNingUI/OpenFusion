OpenFusion 项目架构图

Rust 多模型融合网关：统一接入 OpenAI、Google GenAI、Anthropic 等协议，并行调度 worker 模型，再由 judge 模型综合输出。

Rust 2024 tokio axum reqwest rmcp tower

主链路

入口

CLI / HTTP / MCP

src/main.rs 加载配置并选择 HTTP 模式或 MCP stdio 模式。

运行配置

src/config.rs 解析 server、fusion、judge、workers、storage。

协议适配

HTTP Router

src/server.rs 负责路由、CORS、trace、并发限制和 SSE 判断。

Intermediate 格式

src/protocol.rs 统一请求、响应、工具调用、usage 和流式事件。

融合引擎

FusionEngine

src/engine.rs 判断直达 judge 或并行运行 workers。

SessionStore

src/engine/session.rs 保存、读取、导出融合会话。

模型执行

Workers

多个模型并行探索，使用 VFS 与搜索工具产出候选答案和文件变更。

Judge

吸收 worker 上下文，生成最终答案或继续返回真实工具调用。

Worker Adapter

src/worker/adapter.rs 构造上游请求、解析响应、处理工具循环和 streaming。

输出

协议回填

把 IntermediateResponse 转回 OpenAI、Gemini 或 Anthropic 原生响应。

观测与存档

返回 health、metrics，并将融合结果记录为 session。

Runtime 设计稿

Runtime: if LatestEffectiveTurn is RealUser and tools are not empty, run worker, collect proposals, arbitrate VFS changes, inject enhanced context, then run judge. Otherwise run judge directly with the original or context request. 
Runtime: {
    if (LatestEffectiveTurn() === Turn::RealUser && ToolsNotEmpty()) {
        AIClient.LoadUserPrompt()
            -> Worker(
                GetOriginalRequest()
                    + GetWorkerHarnessPrompt()
                    + GetVfsSummary()
            )
            -> CollectWorkerProposals()
            -> Arbitration(GetVfsChanges())
            -> (() => {
                originalRequest := GetOriginalRequest()
                workerProposal := GetWorkerProposal()
                vfsArbitration := GetVfsArbitration()

                enhancedContext := workerProposal + vfsArbitration
                enhancedRequest := originalRequest.InsertSystemMessage(enhancedContext)

                SetRequest(enhancedRequest)
            })()
            -> AIClient.Run(Judge({
                request: GetRequest()
            }))
            -> Runtime
    } else {
        AIClient.Run(Judge({
            request: GetOriginalRequest() || AIClient.GetContext()
        }))
            -> Runtime
    }
}

模块职责

server

src/server.rs, src/server/health.rs

HTTP 路由、请求计数、SSE 响应、健康检查和 metrics。

protocol

src/protocol/*

四种外部协议和统一中间格式之间的双向转换。

engine

src/engine.rs, src/engine/session.rs

worker 并发调度、min_workers 校验、judge 上下文注入和会话归档。

worker

src/worker/*

上游模型调用、工具调用循环、hook 策略和流式事件收集。

sandbox

src/sandbox.rs, src/sandbox/vfs.rs

为 worker 提供隔离虚拟文件树，并对候选文件变更做仲裁。

mcp

src/mcp/*

stdio MCP 服务，提供 fusion_diff、fusion_bench、fusion_session。

请求执行步骤

  1. 接入请求。HTTP endpoint 或 MCP tool 收到调用。
  2. 协议归一。适配器转换为 IntermediateRequest。
  3. 路径判断。无工具或工具续答时直接进入 judge。
  4. 并行探索。workers 使用独立 VFS 和工具循环生成候选结果。
  5. 上下文注入。引擎汇总成功 worker 与 VFS 仲裁结果。
  6. 最终输出。judge 生成响应，协议层转回调用方格式并保存 session。
